# Hesio

面向团队协作的沟通与工作组织软件，让讨论、任务、交付和反馈围绕同一件工作展开。

> 项目状态：需求分析与产品设计阶段。本 README 描述产品目标与规划，不代表相关功能已经实现。技术栈、部署方式与运行说明将在代码落地后补充。

## 项目背景

团队协作中的困难，往往出现在消息与实际工作之间：讨论分散在不同群聊中，任务缺少明确的负责人，交接需要反复解释背景，成果与贡献也难以完整追溯。

Hesio 希望将沟通与工作事项结合起来，减少信息查找、重复沟通和协作交接的成本，同时保持清晰、易用的交互体验。

## 设计目标

- **沟通有上下文**：围绕具体工作展开讨论，使相关消息、资料与决策能够集中查阅。
- **工作有明确归属**：明确负责人、协作者、预期成果与完成条件。
- **协作能够顺畅衔接**：让进展、依赖、阻碍和交接要求清晰可见。
- **任务与能力相匹配**：结合成员的能力技能与任务要求，为工作分配提供依据。
- **贡献获得公平认可**：结合实际产出、协作支持与反馈呈现贡献，避免单纯以消息数量或在线时长衡量投入。

## 核心业务设计

### 统一工作事项

以“工作事项”作为组织协作的基础单元，将相关讨论、参与人员、资料、进展与交付成果关联起来。

一个工作事项计划包含：

| 信息 | 用途 |
| --- | --- |
| 标题与目标 | 说明需要完成什么、为什么要做 |
| 负责人及协作者 | 明确责任归属与参与关系 |
| 状态与时间安排 | 展示当前进度及预期完成时间 |
| 技能与任务要求 | 为任务分配提供参考 |
| 讨论、资料与决策 | 保留完整协作上下文 |
| 依赖与阻碍 | 说明推进条件和需要的支持 |
| 交付成果与验收条件 | 明确完成标准 |
| 贡献记录与反馈 | 支持工作回顾与公平认可 |

### 围绕事项的沟通

计划支持将讨论与工作事项关联，并将需要执行的讨论结果转为事项，让沟通能够自然进入后续执行流程。

### 能力与任务匹配

以任务要求和成员技能为基础，辅助团队识别适合参与工作的成员。匹配结果用于支持分工决策，具体规则与交互方式将在后续设计中细化。

### 真实贡献与公平认可

将交付成果、问题解决、协作支持等作为贡献记录的依据，并结合反馈帮助团队理解成员的实际投入。具体评价机制将在后续设计中完善。

## 交互方向

- **个人工作台**：集中查看自己负责、参与以及需要跟进的工作。
- **团队工作视图**：了解事项进度、责任分配与协作阻碍。
- **事项详情页**：集中呈现目标、讨论、资料、决策、交付与反馈。
- **沟通入口**：方便团队交流，并将需要持续跟进的信息关联到具体事项。

交互设计以减少切换与重复录入为目标，优先保证核心协作流程清晰可用。
